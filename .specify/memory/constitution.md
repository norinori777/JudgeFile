# JudgeFile 憲法

## 基本原則

### I. 決定的処理優先
ファイル監視、拡張子判定、抽出、振り分け、再実行時の挙動は、同一入力に対して
同じ結果を返す決定的な処理を優先する。AI は補助判定に限定し、最終判断を隠す
抽象化は増やさない。

### II. 構造化AI出力と検証
AI の応答は JSON などの構造化形式を必須とする。スキーマ検証に通らない出力、
必要項目が欠ける出力、ルールと矛盾する出力は採用しない。プロンプトは短く、
分類基準は固定する。

### III. 低信頼度は自動実行しない
信頼度が閾値未満の結果は自動移動せず、review へ送るか人間確認に回す。曖昧な
判定を保存先の最終決定として扱わない。誤振り分けの少なさを自動化率より優先する。

### IV. 抽出・分類・振り分けを分離し監査可能にする
抽出、分類、振り分け、確認を独立責務として実装する。OCR、PDF、Office などの
抽出処理は AI 分類と混在させない。どの入力を送り、何が返り、どう処理したかを
追跡できる監査ログを残す。

### V. 小さく始めて拡張する
初期対応は txt と md を優先し、PDF、画像 OCR、Office は段階的に追加する。依存
ライブラリは最小限に抑え、必要性が明確になるまで LangChain のような抽象は導入
しない。新しい形式や機能は既存の review ルートを壊さず追加する。

## 技術方針と運用制約

- 実装言語は Node.js と TypeScript を基本とする。
- AI 連携は OpenAI SDK を基本とし、必要性が明確な場合のみ LangChain を限定利用する。
- watcher / extractor / classifier / router / logger を分離し、責務を横断させない。
- 機密情報と個人情報は AI 送信前に除外またはマスキングする。
- ファイル本文は必要最小限だけ送信する。
- 生成される spec.md, plan.md, tasks.md, checklist.md は原則日本語で記述する。
- 追加する抽象は、重複する責務を増やさないものに限る。

## 品質基準と変更管理

- すべての分類結果は再現可能でなければならない。
- 失敗時は処理を中断し、誤った振り分けを継続しない。
- 処理ログから原因を追跡できることを必須とする。
- 仕様変更はタグ体系、分類基準、保存先ルールを明示して行う。
- プロンプト変更は出力スキーマと必ずセットで見直す。
- 振り分けロジック変更では review ルートを維持する。
- 例外処理を省略せず、失敗時の挙動を先に決める。
- 本プロジェクトは完全自動の無確認移動を最優先にはしない。
- 本プロジェクトは LangChain 採用自体を目的にしない。
- 本プロジェクトは AI による自由文章生成を主用途にしない。
- 初期段階で大規模な汎用文書管理システムにしない。

## Governance

- この憲法は他の運用ルール、テンプレート、個別タスクより優先する。
- 変更提案は差分、影響範囲、移行方針を明示して行う。
- 変更時は本ファイルを更新し、Constitution Check、仕様、計画、タスクの整合を確認する。
- 版管理はセマンティックバージョンを用いる。
	- MAJOR: 基本原則の削除または非互換な再定義
	- MINOR: 原則や節の追加、または実質的な拡張
	- PATCH: 文言修正、明確化、非意味的な改善
- すべての PR、レビュー、仕様作成、計画、タスク生成では本憲法への適合を確認する。
- 逸脱がある場合は Complexity Tracking か同等の欄で理由を明記する。
